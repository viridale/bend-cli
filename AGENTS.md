- Before starting a new session writing Bend, run `bend version` and read all of `bend guide`; read `bend guide shaders` before parallel or graphical work.
- State each requirement as a law in `LAWS.bend` before writing its code, and put the law diff up for review before proving it.
- Type-check a law diff against stub signatures in `tmp/` before review with `tools/lawcheck.sh -p tmp/stub.bend` (stub defs with `?TODO` bodies, appended to `cli.bend` in a copy): TODOs rise by exactly the new laws over `main`; a planted type error fails.
- Make each golden separate the rule from its likeliest bug (fallthrough, opposite rule, neighbouring limit); pin every exposed field, define duplicate keys, and see old code fail each new fixture.
- Laws can't quantify over `~` arguments: prove a twin taking the callback as a value, forward the public def to it, and bridge with a generic callback.
- Never delete or weaken an accepted law to pass a check; prove every law in `PROOF.bend` and require `bend PROOF.bend` to pass.
- Expect `bend LAWS.bend --check-only` to fail with one TODO per open law once the laws type-check; `bend PROOF.bend` is what closes them.
- Generate goldens from a native harness and smoke-test them natively before `bend PROOF.bend` (~30s; `--verdict` ~2m). Iterate lemmas in a `tmp/` file importing `../LAWS.bend` (<1s), watching the TODO count; after changing a def older proofs walk, rerun all of PROOF.bend.
- `bend` won't run or `-o` a file importing LAWS.bend while laws are open; harnesses import `cli.bend`, inline fixtures, and define `main`.
- In a proof, `%e : P` with `e : {a == b}` needs the goal to be `P` with `_` as `b` and leaves `P` with `_` as `a`, so state a lemma with the side to remove on the right; a rewrite's proof term is a use of what it names and its motive is not, so mark `+` on a parameter that both the rewrite and the rest of the proof use.
- A failed `{==}`'s `expected` is the left side computed; copy goldens from it. The checker stops at the first failure: probe one law per file with `tools/perlaw.sh PROOF.bend [regex]`, which prints each failing law's expected/observed lines; bisect overflows to one-line laws under `timeout 60`; prove long golden strings via the `pieces` lemma (`BUN_JSC_useConcurrentJIT=0` makes flaky overflows reproduce).
- `--verdict`'s generic mismatch hides the reason: `tools/kernel.sh [PROOF.bend]` runs the cached kernel `~/.bend/bendtt/<hash>/bendtt` (by hash, not date) on `bend PROOF.bend -o P.bendtt` and names the def it rejects and why ("out of fuel", or expected/observed).
- Keep `F32.read` out of laws: the checker does not reduce it, so even `{F32.read("1.5") == Some{1.5}}` cannot be proved.
- Keep large `Nat` literals out of laws: the checker's `Nat` is unary and it normalizes both sides, so even `{nat_of("100000") == 100000n}` overflows its stack; state the value as `Nat.read`'s answer and prove it through a lemma over an abstract string.
- Lay out `main.bend`, `LAWS.bend`, and `PROOF.bend` as Bend's demos do: a header comment with purpose, expected output, and run command; laws through an import alias; one proof def per law.
- Keep decisions in pure functions over `Data` with the IO in a thin shell; match every `Result` and close every handle on every branch. Recurse on the input's structure; `Nat` fuel only where none exists, since fuel blocks universal laws and fails silently.
- Keep `main.bend`, `@unsafe`, and `.c`/`.js` effects out of LAWS/PROOF's whole import graph: one unused import fails every law ("defs rely on unsafe or foreign code", bendlang/bend#1463). Such files get no `--check-only` run line.
- Define a def above its first caller, put the matched argument first (a later one costs `--verdict` quadratic fuel), and annotate every operator and every `<-` bind; check with `tools/chk.sh f.bend` (`--check-only`, less the foreign-code list expected of files reaching `run.bend`) after each def.
- `match` heads a def body or `case` arm, on a parameter or pattern variable, scrutinees in parameter order; inside `do`, after a let or `%`, on a call result or destructured pair, or after a match on a later binder, give it its own def.
- Read these checker errors as rules: "an unfilled law is a dead claim" is a call above its def; "a type for this operator" in a pattern means `case 1n+p:` unspaced, and inside `(… : T)` means an unspaced successor `Nn+e` took the rest as its operand, so write `(5n+x) - 4n`; "expected : '='" at a later line means an unspaced `x+y` read `+y` as a let binder; "non-inferrable term" on a conjunction means prove it with `({==}, {==})`; "expected : Data" means a `&2` element isn't Data (a function, tuple, or `Type` parameter), so drop the `&2` or use a `type` record (`Maybe<Dec(A)>`, `List<Call(A)>`).
- Also: "expected : a pattern" after a `<-` is a plain let in `do` (move the rest to a helper); "expected : '('" is a def with no parameters (`def t():`); "expected : Quant" is a missing leading `~&2` (`bend base Name`); "duplicate declaration" is a Base constructor (`Halt`, `Done`, `Ready`, `Move`, `Unit`); "expected : an escape" wants `\u{1B}`.
- Match a callback's quantities exactly: a def with `x` does not fit `@+x: A -> B`, nor one with `+x` fit `@x: A -> B`, so change the def's parameter or pass `x => f(x)`.
- `main() -> IO(U32)` exits 0; exit via `IO.die` (1–255). `IO.print` appends `\n`; `IO.write` doesn't.
- Fork with `a b = f(x) g(y)` over halves of equal work, splitting on a `Nat` depth with the midpoint at `i + (1 << p)`; leaves run a flat tail loop over 8 to 64 items. A head-and-tail recursion runs on one core, and a non-flat call before a fork caps it near 2x.
- Use `Array` for data that is indexed or updated in place, a tree for data a fork splits, and a list for data a leaf walks once.
- Write `+` only for a second use, where one use in each of two exclusive `match` arms is not a second use, and `Array.clone` only for a second array. `+` goes on let and `<-` binders too; a law variable can't take one (forward to a typed helper with `+c: T`); `-x` marks a type-only use; the checker never flags a needless `+`.
- Count `term_keep`, `ctr_take`, and `rfc_seal` per def with `tools/rc.sh` on the emitted C: a seal wraps an unshared constructor in a new heap cell, a keep does the same or an atomic add, and a take on a shared value adds an atomic load and a free or a fade. A rise in a hot def (a per-item loop or a device def) is a regression; record any other rise with its reason in `bench/rc.txt`: moved from an inlined callee, or a lower keep+take+seal total across the changed defs.
- Expect a def to borrow or take its argument according to all of its reachable callers, so a new caller can add or remove keeps and takes in defs whose source did not change; trace such a change to the callee whose segment switched between `term_peek` (borrow) and `ctr_take` (take). One temporary argument made `String.length` take everywhere, and binding it to a name first restored the borrow.
- Expect every argument to be evaluated before its call, including both branches of `Bool.pick` and both sides of `Maybe.or`. Put work that only one outcome needs, such as a failure message or the rest of a search after a hit, in a `match` arm of a helper def.
- Pass a callee the fields it reads, not their record. Records flatten in C, so a `+` on one costs a keep per field (about 7 for `Matches`), and destructuring a constructor only to rebuild it for a call costs a `+` per reused field.
- Have a lookup return what it found as a `Maybe` and branch on that; never test membership and then search again.
- Find a def in the emitted C as `FID_<FILE>_<DEF>` in upper case, named after its file rather than its import alias, with continuations at `_K<n>`; an inlined def may have none.
- Verify a refactor by building one harness to C and native from the old and new code, requiring byte-identical output, and comparing `tools/rc.sh new.c old.txt` per def and in total, where `old.txt` is `tools/rc.sh old.c`.
- Keep the first `--`, `--threads`, `--gpu`, `--gpu-build`, and `--bend-help` out of app options, values, and tests; the runtime consumes them before `main` sees argv (README, Platform notes).
- Launch compiled JS under Bun as `bun app.js -- -- args`: Bun removes a `--` right after the script path, and the runtime removes the next.
- Test generated shell scripts in real shells at CI's oldest versions; drive bash TAB through a pty (a faked `COMP_WORDS` hid a bug).
- Build the deployment target; run it with `--threads 1` and with all cores, confirm equal output, and report the speedup.
- Benchmark with `tools/bench.sh harness.bend args…` (idle `uptime`, a detached main worktree, alternating A/B, median of 5, peak RSS, `--threads 1` over all cores) on shallow and deep inputs; `sample <pid>` names the hot `WL_FID_<DEF>`.
- Commit straight to `main`; push only when asked, then watch CI until it finishes.
- Run `bend PROOF.bend --verdict` last; report commands, outputs, and open holes, since a passing proof covers only its stated laws.
